Ton app, sur GitHub et Supabase.

Ce paquet contient l’application avec ses vrais formulaires et son administration. Le code du site est hébergé sur GitHub Pages ; Supabase protège les comptes, les données et les photos.

1. Crée un projet Supabase

Sur Supabase, crée un projet gratuit et choisis une région proche de tes utilisateurs. Le mot de passe PostgreSQL reste privé et n’est jamais nécessaire dans le site.

2. Installe la base

Dans SQL Editor → New query, copie le contenu complet de supabase/001_cadrivolt.sql et clique sur Run. Fais-le une seule fois, dans un projet neuf, avant de créer les comptes. Ce script crée les tables, les autorisations et le stockage des photos.

Si un compte existait avant l’installation, le script ne le migre pas automatiquement : crée un nouveau compte après l’installation ou demande une reprise des comptes existants.

3. Renseigne les deux valeurs publiques

Dans les paramètres API du projet, récupère Project URL et la clé publishable (ou l’ancienne clé anon). Modifie config.js :

window.CADRIVOLT_CONFIG = {
  supabaseUrl: "https://TON-PROJET.supabase.co",
  supabasePublishableKey: "TA_CLE_PUBLIQUE"
};

Conserve la dernière ligne du fichier, qui calcule l’adresse du site. La clé publique est prévue pour le navigateur ; les fonctions SQL contrôlent les accès. Aucune clé secret/service_role ni aucun mot de passe ne doit être ajouté aux fichiers GitHub.

4. Dépose les fichiers sur GitHub

Décompresse le ZIP et ajoute son contenu à la racine du dépôt : index.html, assets, images, admin, reset, config.js et les autres fichiers. Dans Settings → Pages, choisis Deploy from a branch → main → /(root), puis Save. GitHub affiche l’adresse de l’app.

Le site fonctionne aussi sous https://TON-COMPTE.github.io/TON-DEPOT/. Aucun npm install ni serveur Node n’est nécessaire sur GitHub Pages.

5. Configure les e-mails de connexion

Dans Supabase Authentication → URL Configuration, mets l’adresse exacte de ton app, avec le slash final, dans Site URL. Ajoute cette adresse et https://TON-COMPTE.github.io/TON-DEPOT/reset/ dans les adresses de redirection autorisées. Pour les essais locaux, ajoute aussi leurs adresses exactes.

Garde la confirmation des e-mails activée. Configure un fournisseur SMTP dans Authentication pour les confirmations et les récupérations de mot de passe. Le service e-mail par défaut de Supabase est limité aux adresses autorisées de l’équipe et à un petit quota ; il ne suffit pas aux inscriptions publiques.

Pour ton premier essai, utilise l’adresse de ton compte Supabase autorisée par son service e-mail. Pour ouvrir les inscriptions à tous, la configuration SMTP est nécessaire. Les éventuels coûts et quotas de ce fournisseur sont distincts de Supabase.

Dans les réglages de sécurité des mots de passe Supabase, règle également la longueur minimale à 12 caractères. Le formulaire impose déjà cette longueur, mais le réglage Supabase protège aussi les appels directs.

Photos de profil

Après le script 001, exécute 007_profile_photos.sql. Les membres pourront ajouter, remplacer et retirer leur photo depuis Mon profil. Formats JPG, PNG ou WebP, 8 Mo maximum. La photo est publique ; retirer la photo du profil ne supprime pas le fichier du stockage.

6. Active ton administration

  1. Crée ton compte sur Cadrivolt et confirme l’e-mail reçu. Tu peux choisir le mot de passe que tu avais prévu pour l’administration.
  2. Ouvre supabase/002_admin.sql, remplace REMPLACE_PAR_TON_EMAIL par ton adresse, puis exécute le script dans SQL Editor.
  3. Ouvre TON-ADRESSE/admin/ et connecte-toi avec ton e-mail et ton mot de passe.

Aucun premier inscrit ne devient administrateur automatiquement. Aucun mot de passe n’est embarqué dans le dépôt.

7. Notifications dans le site et sur téléphone

Après le script 001, exécute 004_notifications.sql, puis 005_web_push.sql. Déploie la fonction cadrivolt-push depuis supabase/functions/cadrivolt-push/index.ts, avec sa configuration dans supabase/config.toml. Elle vérifie les connexions des membres et le jeton privé du planificateur. Exécute ensuite 006_push_schedule.sql.

Connecte-toi, ouvre la cloche et clique sur Activer sur cet appareil. Sur iPhone (iOS 16.4+), ajoute le site à l’écran d’accueil via Safari, puis ouvre cette icône. Un bouton permet de tester l’envoi. Le traitement a lieu chaque minute ; la réception dépend du navigateur et des réglages du téléphone. Aucun abonnement SMTP n’est nécessaire pour le push.

8. Vérifie avant d’inviter la communauté

Crée deux comptes, publie une annonce depuis le premier et demande à participer depuis le second. Vérifie les messages, l’acceptation, l’envoi d’une photo et la récupération du mot de passe. Vérifie ensuite qu’un membre ordinaire n’accède pas à /admin. Les tests du paquet ont validé le SQL localement ; ces essais confirment la configuration de ton vrai projet.

Données, sauvegarde et limites gratuites

L’administration permet de modifier l’accueil, les profils, les annonces, suspendre des membres et exporter les données métier. Les mots de passe restent gérés par Supabase Auth et ne figurent jamais dans cet export. Pour une sauvegarde complète et les photos, utilise les outils Supabase séparément.

Le plan gratuit Supabase annonce 500 Mo de base, 1 Go de fichiers et des quotas de transfert. Un projet inactif peut être mis en pause après une semaine. Les quotas sont partagés par les fonctions de ton projet ; ce n’est pas un hébergement illimité.

Les images du stockage sont publiques. Les messages et demandes sont accessibles aux participants et à l’administrateur. Les paiements ne sont pas traités dans l’app.
